## 3. What Went Well

### 3.1 Story Spec Quality
Every story included a "Current State of Code" table listing existing files, their state, and whether to reuse/extend/create. "Previous Story Intelligence" sections ensured agents didn't reinvent patterns. This dramatically reduced wasted work compared to earlier epics.

### 3.2 Architectural Consistency Across Exercise Types
Stories 4.4-4.8 (5 exercise types) all followed the same integration pattern: add a case to the `play.tsx` exercise type switch, wire `onComplete`, reuse `FeedbackOverlay` and `useSound`. By Story 4.6, the pattern was so well-established that agents could follow it with minimal deviation.

### 3.3 Test Coverage as First-Class Citizen
Every story shipped with co-located unit tests. Story 4.11 alone had 165 tests. Story 4.12 added 65 tests. The testing anti-patterns from Epic 3 (barrel-file imports breaking tests, missing mocks) did not recur.

### 3.4 Code Review Catching Real Issues
Code review consistently caught HIGH-severity issues: `@ts-expect-error` build-breaker (4.11), infinite navigation loop (4.2), 36px Chinese font violation (4.5), redundant `startQuiz` overwriting persistence metadata (4.10). The review process served as an effective safety net.

### 3.5 Structured Content Migration (Story 4.14)
Clean architectural evolution from RAG-only to structured-first-with-RAG-supplementary without changing the mobile API contract. Zero backward compatibility breaks. Grammar coverage enforcement (FR58) added to validation.

### 3.6 Evaluator-Optimizer Pattern (Story 4.13)
LLM-based content evaluation catches Traditional Chinese violations, pinyin diacritics issues, and question language problems. Self-correction loop with max 2 retries and graceful degradation.

## 4. What Didn't Go Well

### 4.1 Pre-Existing Test Failure Never Fixed
The `useChapters.test.ts` chapter title mismatch (from Story 3.2) was noted in 10+ story completion records. Epic 3 Action Item A5 specifically required fixing it. It was never addressed. This represents a "broken windows" culture risk.

### 4.2 Code Review Found Too Many HIGH Issues
While code review worked as a safety net, the volume of HIGH-severity issues suggests first-pass implementation quality needs improvement:

| Pattern | Stories Affected |
|---------|-----------------|
| Missing or broken tests | 4.1, 4.2, 4.5, 4.7, 4.10, 4.11, 4.13 |
| State management bugs (race conditions, stale closures) | 4.4, 4.5, 4.7, 4.10 |
| UX spec violations (font sizes, colors, navigation) | 4.2, 4.5, 4.9, 4.11 |
| Dead code or unused props/state | 4.1, 4.5, 4.9, 4.10 |
| Timer/effect cleanup issues | 4.2, 4.7, 4.8, 4.9 |

### 4.3 Infrastructure Action Items Ignored
Three Epic 3 action items (A4 E2E CI, A5 test fixes, A8 dead route) were never addressed. Infrastructure improvements consistently lose priority to feature work.

### 4.4 Premade Exercise Data Gap
The seeding pipeline (Story 11.4), database table (`premade_exercises`), UI (Story 3.5), and completion flow (Story 11.8) all exist, but the table has not been populated with real workbook data. This gap prevents the full exercise selection experience.

## 7. Key Learnings

1. **Story spec quality directly correlates with implementation quality.** The "Current State of Code" tables and "Previous Story Intelligence" sections paid for themselves many times over.
2. **Architectural patterns compound.** Once the exercise type integration pattern was established in Stories 4.3-4.4, the remaining 4 exercise types (4.5-4.8) implemented cleanly.
3. **Infrastructure items need dedicated stories, not action items.** Three Epic 3 action items were ignored because they competed with feature work. Next time, create explicit stories for infrastructure improvements.
4. **Code review is necessary but should not be the primary quality gate.** The volume of HIGH issues caught in review suggests implementation checklists or pre-review self-checks would help.
5. **Data pipeline verification must happen before building features that depend on the data.** The premade exercise gap should have been caught earlier.
